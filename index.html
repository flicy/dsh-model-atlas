DSH 模型全景概览

DeepSeek Harness 可通过多种方式接入几乎所有主流大语言模型

◉
DSH 能接入哪些模型？

DSH 的模型接入层 dsh-llm-pi-ai 兼容 OpenAI Chat Completions 协议，凡是支持该协议的 API 均可即插即用。从类别上分为：

  • 内置 Provider — DeepSeek（原生协议）、Anthropic、OpenAI、Azure、Bedrock、Vertex、Codex
  • 自定义 OpenAI 兼容 — 任意兼容 OpenAI 格式的 API 端点（Grok、Together AI、Groq、vLLM、Ollama 等）
  • 聚合网关 — 通过 TokenDance 等聚合平台，一次接入数十个模型（当前使用的方案）
  • 本地模型 — 通过 Ollama / vLLM 本地部署，暴露 OpenAI 兼容接口后接入

Providers

Provider 接入方式详解

DSH 支持 6 种不同的模型接入方式

⚡
DeepSeek 原生 原生协议
最简配置，安装后直接用。DSH 原生支持 DeepSeek 协议，Web UI 填入 API Key 即可自动获取模型列表。
Web UI: 设置 → 模型 → DeepSeek 卡片 → 输入 API Key → 保存
📦
内置 Provider 目录 Anthropic / OpenAI
点"添加 Provider"，选择服务商，填写凭据即完成配置。Azure 需要 api-version，Codex 使用 OAuth 认证。
Web UI: 设置 → 模型 → 添加 Provider → 选择 → 填 Key → 保存
🔧
自定义 Provider openai-completions
任意 OpenAI 兼容 API 端点，手动填写 Provider ID、Base URL 和模型列表。
llm-pi-ai: providers: groq: displayName: Groq apiKeyEnv: GROQ_API_KEY api: openai-completions baseURL: https://api.groq.com/openai/v1 models: - id: llama-3.3-70b-versatile
🎨
多模态配置 text + image
视觉模型需显式声明 input 模态。支持图片输入的模型会在发送前校验。
llm-pi-ai: providers: my-gateway: models: - id: vision-model input: [text, image]
🔄
聚合网关 TokenDance
你当前使用的方案。通过一个 API Key 接入数十个模型，统一计费和管理。
baseURL: https://tokendance.space/gateway/v1 api: openai-completions models: [deepseek-v4-flash, qwen3.8-max, glm-5.2, kimi-k3, minimax-m3, ...]
🖥️
本地模型 Ollama / vLLM
本地部署开源模型后，通过 Ollama 或 vLLM 暴露 OpenAI 兼容接口。
llm-pi-ai: providers: ollama: api: openai-completions baseURL: http://localhost:11434/v1 models: - id: llama3.3

自定义settings.yaml 中配置 baseURL / apiKeyEnv / models

Architecture

DSH 模型层架构

理解 DSH 的模型接入层设计原理

1
插件化架构PLUGIN-BASED

DSH 的模型能力由 dsh-llm-pi-ai 插件提供。PI = Provider Interface，统一模型接入接口。每个 Provider 定义 baseURL、api（协议）、apiKeyEnv（凭据环境变量），模型列表在 models 字段中声明。

2
配置层次CONFIG LAYERS

DSH 配置由多层叠加而成：Bundle 默认 → Profile 配置 → 用户 ~/.dsh/settings.yaml（最高优先级）。用户配置覆盖默认值，无需修改插件包。

3
凭据管理CREDENTIALS

API Key 以只写方式存储在 $DSH_HOME/.credentials.yaml，Web UI 只显示遮盖版本。支持通过 apiKeyEnv 引用环境变量（推荐做法）。

4
请求生命周期REQUEST FLOW
  • 用户发送消息 → Agent 循环决定调用 LLM
  • Provider 选择 → 根据会话模型定位 Provider 配置
  • 凭据注入 → 从 credentials/环境变量读取 API Key
  • API 调用 → 按 baseURL/protocol 发送请求
  • 流式返回 → SSE 流式输出，实时展示
  • 错误重试 → dsh-llm-retry 插件自动处理

Quick Start

5 步快速配置模型环境

从零开始，5 分钟配置好 DSH 模型环境

1

安装 DSH

确保已安装 Node.js 18+，然后运行：

npx @deepseek-ai/dsh web

或从源码安装：

git clone https://github.com/deepseek-ai/deepseek-harness.git cd deepseek-harness pnpm install && pnpm run build && pnpm dsh web
2

配置模型 Provider

打开 Web UI 的 设置 → 模型 页面，添加 Provider：

# 或直接编辑 ~/.dsh/settings.yaml llm-pi-ai: providers: my-gateway: displayName: 我的网关 apiKeyEnv: MY_API_KEY api: openai-completions baseURL: https://your-gateway.com/v1 models: - id: model-a - id: model-b
3

设置环境变量

在终端中设置 API Key 环境变量（或通过 Web UI 保存）：

export TOKENDANCE_API_KEY="your-key-here" # 建议写入 ~/.zshrc 或 ~/.bashrc 持久化
4

选择工作区

在 Web UI 中点击"选择工作区"，添加你的项目目录，选中它。只有选中工作区后才能发送任务。

5

选择模型并开始

新建会话，在模型选择器中选择你配置的模型。模型切换即时生效，无需重启服务器。

# 常用 CLI 命令 dsh web # 启动 Web UI dsh --profile headless "..." # 无头模式 dsh --profile web --dump-config # 查看完整配置
